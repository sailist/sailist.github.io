总述#

vscode 中可以执行的 item，有 Command 和 Action 两种，这两种都可以通过某些方式被触发，且都可以分配 Keybinding。这些 Execuable，又分两类，一类是有历史栈的（可以 undo/redo），一类是没有历史栈的。

  • 所有的 Action 都通过 registerAction2 来注册，通过 registerAction2 注册的 Action 可以出现在各种 Menu 中，并分配 Keybinding。这实际上是分别通过 CommandsRegistry.registerCommand、KeybindingsRegistry.registerKeybindingRule 和 MenuRegistry.appendMenuItem 完成的

  • 所有的 Command 都继承抽象类 Command，调用 registerCommand 时，其实是调用 Command 类实现的 register() 方法，该方法只会走 CommandsRegistry.registerCommand 和 KeybindingsRegistry.registerKeybindingRule， MenuRegistry.appendMenuItem

ICommandService & IInstantiationService#

ICommandService 是最终负责执行 Commands 的服务接口，而 IInstantiationService 则是所有函数调用的接口，基于该入口调用的函数可以被追踪，用于 Profile 或问题分析

export class CommandService extends Disposable implements ICommandService {
	private _tryExecuteCommand(id: string, args: any[]): Promise<any> {
		const command = CommandsRegistry.getCommand(id);
		if (!command) {
			return Promise.reject(new Error(`command '${id}' not found`));
		}
		try {
			this._onWillExecuteCommand.fire({ commandId: id, args });
			const result = this._instantiationService.invokeFunction(command.handler, ...args);
			this._onDidExecuteCommand.fire({ commandId: id, args });
			return Promise.resolve(result);
		} catch (err) {
			return Promise.reject(err);
		}
	}
}

export class StandaloneCommandService implements ICommandService {
	declare readonly _serviceBrand: undefined;

	private readonly _instantiationService: IInstantiationService;

	private readonly _onWillExecuteCommand = new Emitter<ICommandEvent>();
	private readonly _onDidExecuteCommand = new Emitter<ICommandEvent>();
	public readonly onWillExecuteCommand: Event<ICommandEvent> = this._onWillExecuteCommand.event;
	public readonly onDidExecuteCommand: Event<ICommandEvent> = this._onDidExecuteCommand.event;

	constructor(
		@IInstantiationService instantiationService: IInstantiationService
	) {
		this._instantiationService = instantiationService;
	}

	public executeCommand<T>(id: string, ...args: any[]): Promise<T> {
		const command = CommandsRegistry.getCommand(id);
		if (!command) {
			return Promise.reject(new Error(`command '${id}' not found`));
		}

		try {
			this._onWillExecuteCommand.fire({ commandId: id, args });
			const result = this._instantiationService.invokeFunction.apply(this._instantiationService, [command.handler, ...args]) as T;

			this._onDidExecuteCommand.fire({ commandId: id, args });
			return Promise.resolve(result);
		} catch (err) {
			return Promise.reject(err);
		}
	}
}

一条完整的调用链#

有一个 BulkEditService -> BulkEdit -> BulkFileEdit/BulkTextEdit -> SingleModelEditStackElement -> TextModel._pushEditOperations/_applyUndo/Redo -> textbuffer.applyEdit 的调用链条：

  • 涉及到文本、文件、Cell（notebook）的修改，最终都是通过 BulkEditService 完成的，全局搜索 bulkEditService.apply，可以观察到所有相关的原生操作
  • 涉及到文本的修改，最终会走到 TextModel 的调用逻辑上，其中直接的操作会走到 _pushEditOperations，如果是 undo、redo 会走到 _applyUndo/_applyRndo 方法上
  • TextModel 所有的修改都会通过 TextBuffer 中的 applyEdit 来实现

class BulkEdit {
	// ...
	async perform(): Promise<readonly URI[]> {

		if (this._edits.length === 0) {
			return [];
		}

		const ranges: number[] = [1];
		for (let i = 1; i < this._edits.length; i++) {
			if (Object.getPrototypeOf(this._edits[i - 1]) === Object.getPrototypeOf(this._edits[i])) {
				ranges[ranges.length - 1]++;
			} else {
				ranges.push(1);
			}
		}

		// 对所有 range perform 这一次更改
		for (const range of ranges) {
			if (this._token.isCancellationRequested) {
				break;
			}
			const group = this._edits.slice(index, index + range);
			if (group[0] instanceof ResourceFileEdit) {
				resources.push(await this._performFileEdits(<ResourceFileEdit[]>group, this._undoRedoGroup, this._undoRedoSource, this._confirmBeforeUndo, progress));
			} else if (group[0] instanceof ResourceTextEdit) {
				// 文本相关的更改
				resources.push(await this._performTextEdits(<ResourceTextEdit[]>group, this._undoRedoGroup, this._undoRedoSource, progress));
			} else if (group[0] instanceof ResourceNotebookCellEdit) {
				resources.push(await this._performCellEdits(<ResourceNotebookCellEdit[]>group, this._undoRedoGroup, this._undoRedoSource, progress));
			} else {
				console.log('UNKNOWN EDIT');
			}
			index = index + range;
		}

		return resources.flat();
	}
}

export class SingleModelEditStackElement implements IResourceUndoRedoElement{
	// 原来的文本编辑器类型（应该具体到了某个窗口）
	public model: ITextModel | URI;
	// 编辑的数据类型，记录了 before 的信息（用于 undo）和 after 的信息（用于 redo）
	private _data: SingleModelEditStackData | ArrayBuffer;

	public get type(): UndoRedoElementType.Resource {
		return UndoRedoElementType.Resource;
	}

	public get resource(): URI {
		if (URI.isUri(this.model)) {
			return this.model;
		}
		return this.model.uri;
	}


	public canAppend(model: ITextModel): boolean {
		return (this.model === model && this._data instanceof SingleModelEditStackData);
	}

	public append(model: ITextModel, textChanges: TextChange[], afterEOL: EndOfLineSequence, afterVersionId: number, afterCursorState: Selection[] | null): void {
		if (this._data instanceof SingleModelEditStackData) {
			this._data.append(model, textChanges, afterEOL, afterVersionId, afterCursorState);
		}
	}

    public undo(): void {
        if (this._data instanceof SingleModelEditStackData) {
            this._data = this._data.serialize();
        }

        const data = SingleModelEditStackData.deserialize(this._data);
        this.model._applyUndo(data.changes, data.beforeEOL, data.beforeVersionId, data.beforeCursorState);
    }

    public redo(): void {
        if (URI.isUri(this.model)) {
            // don't have a model
            throw new Error(`Invalid SingleModelEditStackElement`);
        }
        if (this._data instanceof SingleModelEditStackData) {
            this._data = this._data.serialize();
        }
        const data = SingleModelEditStackData.deserialize(this._data);
        this.model._applyRedo(data.changes, data.afterEOL, data.afterVersionId, data.afterCursorState);
    }
}

总结#

所有 文件、文字的修改，都会通过 BulkEditService 来完成，基于 Service 的调用会创建包含了历史信息的上下文，用于 undo redo。不通过 BulkEditService 调用执行的其他 Action 和 Command，都是只有当前状态，没有办法回退的
